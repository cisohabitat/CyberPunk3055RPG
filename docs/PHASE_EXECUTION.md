Run the implementation checks with `npm test`, `npx tsc --noEmit`, `npm run build`, `npm run story:replay`, and `npm run production:report`, and `npm run production:verify`. Build runs the report before the four-browser regression suite, then starts a temporary production server for `production:verify` and the load probe. Oversized media, aggregate compressed script/style budget violations, broken story destinations, invalid authored scenes, and incorrect replay outcomes fail the technical build. Production artifacts are retained for thirty days; browser failure artifacts retain their established seven-day policy.

`qa/production/budgets.json` sets provisional repository regression envelopes: 1 MiB per artwork file, 3 MiB per audio file, 768 KiB aggregate gzip scripts, and 128 KiB aggregate gzip styles, plus a 2 MiB encoded-resource envelope in the cold-context browser probe. The report inventories all static build files, not an assumed initial-route bundle. These limits protect asset growth; they do not establish the full plan’s load, interaction, stability, or long-session device budgets. Hashes identify assets and do not establish rights.

For a running production build, use `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run production:probe -- http://127.0.0.1:3116`, or omit the executable override when using installed Playwright Chromium. The probe compares illustrated/text-only cold contexts at phone and desktop sizes, with 5 Mbps / 150 ms network emulation on phone. It records resource bytes, title LCP, layout shift, goal visibility, and artwork requests. It performs automated character creation; elapsed readiness includes form entry and network-idle waits. Four synthetic samples are not percentile measurements or physical-device certification. No player telemetry is installed or uploaded.

The default report permits technical demo verification while reporting `commercialAcceptanceReady: false`. For commercial candidate review, `npm run production:report -- --release` exits unsuccessfully until every gate in `qa/production/acceptance.json` has a passed status and supporting evidence references. References must exist. A pending or unsupported pass claim cannot become a release-ready report. Populate records only after the corresponding human work has occurred; a checkmark or an asset hash is not a rights or craft review. Existing demo hosting retains its fail-closed Test/Build gate.

Next production work proceeds from the evidence: add routes for uncovered branches, run blind fresh-player sessions, revise comprehension or fatigue issues, have a writer build a second mission through the structured pipeline, lock visual/script models, resolve rights, commission against the locked scope, and complete device/access/localization review before release acceptance. Funding, hiring, commissioning, and outreach are separate production actions, not work claimed by these commits. The overall provisional grade remains 7.0/10 until independent evidence supports a regrade.
